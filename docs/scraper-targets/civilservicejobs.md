# civilservicejobs.gov.uk — scraping notes

**Verified:** 2026-04-22
**Base URL:** `https://www.civilservicejobs.service.gov.uk/csr/index.cgi`
**Search entry:** `https://www.civilservicejobs.service.gov.uk/csr/index.cgi?pageaction=searchpageresults`
**Platform:** WCN (Workforce Computer Networks) ATS — CGI-based

---

## Site structure

The site is a server-rendered CGI application (`index.cgi`, `esearch.cgi`) hosted by WCN. All
pages share a consistent stylesheet served from `static.civilservicejobs.service.gov.uk`.

Session state is carried via SID (base64-encoded URL parameters) and anti-CSRF tokens (`reqsig`,
a timestamp-signed token generated by client-side JavaScript). The search results page requires a
POST to `esearch.cgi` with a valid `reqsig` — this token is only generated by the page's
JavaScript and is time-bound (expires within seconds).

---

## Anti-bot protection

### Altcha CAPTCHA (verified blocker, 2026-04-22)

All requests from a new browser session (any realistic Chrome/Firefox user-agent) are intercepted
by an Altcha proof-of-work CAPTCHA before reaching any page content:

- Title: `Quick Check Needed`
- Widget: `<altcha-widget challengeurl="?ProtectCaptcha=1">`
- Version: `1.1.6` (as shown in page footer)
- Challenge type: SHA-512 PoW, `maxnumber: 300000`
- The challenge endpoint (`?ProtectCaptcha=1`) itself returns a JSON challenge — it is accessible
  without CAPTCHA, but the form auto-submission requires JavaScript to compute the solution and
  POST back to proceed.

**Playwright headless Chrome is blocked.** Even with playwright-stealth, the sandbox IP was
flagged and the Altcha widget did not auto-solve (remained `data-state="unverified"`) across
multiple attempts.

### Googlebot bypass (confirmed working, 2026-04-22)

Using UA `Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)` bypasses the
Altcha CAPTCHA entirely. However, pages served to the Googlebot UA are **simplified** — they
omit the JS-generated `reqsig` CSRF token from the search form, so form submission via POST still
fails (server rejects requests without a valid `reqsig`). The Googlebot UA gets the search form
page but cannot produce search results.

### reqsig token

The search form action URL is:

```
https://www.civilservicejobs.service.gov.uk/csr/esearch.cgi?SID=<base64-reqsig>
```

The SID appended to the action URL decodes to `reqsig=<unix-timestamp>-<hmac-hex>` — a
time-limited anti-replay token generated by client-side JS. Without it, POSTing the search form
returns a redirect back to the home page.

## Unblocking strategies

### Option A: Solve Altcha in Playwright (recommended)

The Altcha PoW widget should auto-solve in a real JS-enabled browser. The sandbox IP may be
rate-limited or fingerprinted. Options:

1. Clear the `csj-inspect` profile data (in `/home/jkai/scraper-profiles/`) and retry from a
   fresh profile.
2. Wait out the IP block (typically 1–24 hours for PoW-based systems).
3. Configure a residential proxy for the scraper.

Once the Altcha CAPTCHA is passed once, the site sets session cookies (`request_token`,
`request_token_ext`, `request_token_int`, `language`) which persist in the Playwright profile
directory. Subsequent requests in the same profile should not trigger the CAPTCHA.

After the CAPTCHA is cleared, the form still requires `reqsig`. The scraper's JS rendering
_should_ populate this field since Playwright runs a full Chrome instance — the token is only
missing when using the Googlebot UA (which bypasses CAPTCHA but gets a simplified page).

**Recommended approach:**
- Use a normal Chrome UA (not Googlebot) in a trusted Playwright profile.
- First visit: accept the Altcha challenge (may require `waitFor: {type: "timeout", ms: 15000}`
  for the PoW computation to complete and auto-submit).
- Check that the form URL includes a populated `SID` with `reqsig=...` before submitting.
- Then submit the form and follow to results.

### Option B: Cookie injection

If a real browser session has already passed the CAPTCHA, export its cookies and inject them via
the scraper's `cookie` login strategy:

```json
{
  "_credential": {
    "loginStrategy": "cookie",
    "credential": {
      "cookies": [
        {"name": "request_token", "value": "<value>", "domain": ".civilservicejobs.service.gov.uk", "path": "/"},
        {"name": "request_token_ext", "value": "<value>", "domain": ".civilservicejobs.service.gov.uk", "path": "/"},
        {"name": "request_token_int", "value": "<value>", "domain": ".civilservicejobs.service.gov.uk", "path": "/"}
      ]
    }
  }
}
```

## Example ScrapeJob (to use once CAPTCHA is unblocked)

```json
{
  "url": "https://www.civilservicejobs.service.gov.uk/csr/esearch.cgi",
  "profile": "csj-results",
  "waitFor": { "type": "networkidle" },
  "pacing": { "minMs": 2500, "maxMs": 5000 },
  "extract": [
    {
      "field": "result_count",
      "selector": ".search-results-job-count-number",
      "attr": "text"
    },
    {
      "field": "titles",
      "selector": ".search-results-job-box-title",
      "attr": "text",
      "multi": true
    },
    {
      "field": "title_links",
      "selector": ".search-results-job-box-title a",
      "attr": "href",
      "multi": true
    },
    {
      "field": "departments",
      "selector": ".search-results-job-box-department",
      "attr": "text",
      "multi": true
    },
    {
      "field": "locations",
      "selector": ".search-results-job-box-location",
      "attr": "text",
      "multi": true
    }
  ],
  "pagination": {
    "type": "next-link",
    "nextSelector": ".search-results-paging-menu a:last-child",
    "maxPages": 5
  }
}
```

**Note:** This ScrapeJob must be preceded by a form POST to `esearch.cgi` with a valid `reqsig`.
The current runner does not support pre-navigation form POSTs; the URL above is a placeholder.
In practice, the runner should navigate to the search form page first, fill and submit it, and
then apply the extract rules. This requires an `actions` step not yet implemented in scrape.py.

### Alternative: direct GET with SID

Once a search session exists in the profile, the results URL is:

```
https://www.civilservicejobs.service.gov.uk/csr/index.cgi?SID=<encoded-session>
```

Where the SID encodes `pageaction=searching&pageclass=Search&owner=5070000&ownertype=fair&what=...`.
Pagination is driven by the `.search-results-paging-menu` links, which carry updated SIDs.

## Pacing

- 2.5–5s between requests (`pacing: { minMs: 2500, maxMs: 5000 }`).
- Do not exceed 1 request/second sustained.
- The site does not advertise rate limits in `robots.txt` (allows all crawlers except JoobleBot).

---

## Login / auth

- Search results and job detail pages are **public** — no account required.
- The CAPTCHA is the access gate, not authentication.
- "Save job" / job basket features require an account but are not needed for scraping.
- No login credentials are needed for public job listings.

---

## Limitations

1. **Altcha CAPTCHA blocks all automated browsers** from new sessions (2026-04-22). The sandbox IP
   was flagged; the challenge did not auto-solve across 4 Playwright attempts.
2. **reqsig token** is a JS-generated, time-limited CSRF token appended to the search form action
   URL. The scrape.py runner cannot capture and use this without JS execution in a real (non-
   Googlebot) browser session.
3. **No public API or RSS feed** was found for search results. The CGI interface is form-driven.
4. **Salary/grade** are not exposed as named CSS classes in the search result cards; they appear
   to be part of the free-text content inside `.search-results-job-box-no_welsh` and would
   require regex extraction. Full salary data is on individual job detail pages
   (`.vac_display_field_value`).
5. **URL-template pagination** does not work because page URLs encode session state in SIDs, not
   plain page numbers. Use `next-link` pagination only.
6. **Googlebot UA** bypasses the CAPTCHA but produces a simplified HTML response without the
   `reqsig` token, making form submission impossible via that path.
