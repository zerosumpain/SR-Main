2 · Security & data-integrity (the two that mattered most)

#9 — safe-eval RCE bypass closed

The old regex denylist was bypassable with dynamic property access — a working escape (this["cons"+"tructor"]["cons"+"tructor"]("…")()) read process.env at review time. Replaced with an AST allowlist: the expression is parsed (@babel/parser) and every node walked, rejecting this, banned identifiers/property-names (constructor, __proto__, process, Function, eval, …), dynamic computed member access, and Function/eval calls — before any new Function. Signature unchanged, so transform/conditional/validator/loop are untouched. Hand-rolled walk (no visitor-table import, which breaks under vitest's full-graph loading). Test asserts the bypass is rejected and legitimate expressions pass.

src/lib/workflows/nodes/safe-eval.ts · tests/lib/workflows/nodes/safe-eval.test.ts

#1 — node_executions cross-run corruption

Per-run UPDATEs were scoped by nodeId only; since nodeId is the static graph-node id reused on every run, completing one run overwrote the status/IO/cost/timestamps of all prior runs' executions of that node. Now scoped by and(eq(runId), eq(nodeId)) everywhere (mirroring the already-correct resume path), with a mutation-verified test.

run-helpers.ts · scheduler.ts · routes/api/workflows/[id]/run/+server.ts · tests/lib/workflows/run-helpers.test.ts

3 · Engine & runtime

#11 / #10 / #20 — cancellation, drain, durability

  • #11 engine.cancelRun(runId) aborts a live run via a run-level AbortController linked to the per-node timeout controllers; scheduling halts between levels; the cancel route calls it after the DB status flip. (Previously cancel was DB-only and the run kept spending cost.)
  • #10 engine.drain(timeoutMs) stops accepting new runs and awaits in-flight run promises; gracefulShutdown awaits drain(25s) before exit (idempotent under double-SIGTERM).
  • #20 each node's status/output is now persisted at completion (runId-scoped, best-effort), so a crash mid-run preserves finished nodes and aids resume.

engine.ts · engine-runtime.ts · hooks.server.ts · cancel route

#13 / #14 / #17 / #18 — structure, correctness & types

  • #13 extracted mergeUpstreamInput into engine-node-runner.ts (verbatim); the self-healing/retry block was left inline by design (too closure-bound to extract without behaviour risk) and documented.
  • #14 self-healing applies healed config to a per-run copy and no longer writes it back to workflow_nodes — it was silently rewriting the user's saved workflow.
  • #17 fan-in key collisions now emit a warning instead of silent last-writer-wins (merge result unchanged).
  • #18 engine-injected context fields are typed on ExecutionContext, removing inline casts.

#19 — durable run-worker flag-off

Optional separate run-worker process driven by a DB-backed queue. JKAI_RUN_WORKER=1 makes the run route and scheduler enqueue runs (claimed via FOR UPDATE SKIP LOCKED leases) and runs cron under a pg_try_advisory_lock leader, executed by packages/jkai-run-worker. With the flag off, behaviour is byte-for-byte unchanged. Three nullable columns were added to workflow_runs in the schema.

Before enabling: run npx drizzle-kit push to apply the additive columns, build the worker (node packages/jkai-run-worker/build.mjs), and validate on staging before flipping JKAI_RUN_WORKER=1. Until then the in-process model (now hardened by #10/#11/#20) continues to run exactly as before.

5 · New control-flow primitives (#12) note

  • switch — deterministic n-way branch; sets metadata._selectedHandle via the engine's existing n-way routing. (nodes/switch.ts + .def.ts)
  • loop concurrency — the previously-ignored concurrency config now drives a bounded pool; default 1 preserves the old sequential behaviour and output order. (nodes/loop.ts)
  • approval — standalone human approve/reject node reusing the engine pause primitive, with no scraper dependency; an auto-decision fast-path routes on approved/rejected handles. (nodes/approval.ts + .def.ts)
Known limitation: on the human pause→resume path, the resume endpoint seeds a fixed node output, so handle auto-routing doesn't re-fire — branch downstream on input.formValues.approved with a conditional/switch. Making the resumed node re-route on its handle is a small follow-up in the engine + resolve endpoint.
